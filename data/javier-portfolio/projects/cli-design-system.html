The problem

An inconsistent CLI

Docker's CLI had grown organically — inconsistent patterns, styles, and terminology across commands. There was no shared system, so every team reinvented conventions and users faced a hard-to-learn surface.

My role

Creator & owner

Proposed, scoped, and built the system from scratch (Figma + Notion) and set the roadmap. Started from research — co-authored the DockerCon CLI Research Report (10 captains interviewed) — then codified recurring patterns into a company-wide library.

Jobs to be done

What it enables

  • Design a new CLI command that feels consistent with the rest of Docker
  • Reuse proven CLI patterns instead of inventing them
  • Align on CLI terminology and structure across teams
Who it serves

Personas

  • Sam — newcomer who needs a learnable, consistent CLI
  • Every internal team designing CLI surfaces (the design-system's own users)
Impact

Leverage beyond my own pixels

Adopted org-wide (products like Docker Offload build on it) and described internally as becoming "Docker's Organizational Standard" for the CLI. It raises consistency and speed for every team designing CLI experiences — the clearest principal/head-level signal in the portfolio.
