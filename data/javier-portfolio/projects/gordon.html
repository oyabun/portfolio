Origin — the FGPT hackathon (2023)where Gordon began

Gordon traces back to FGPT — "Fellowship of the GPT", a Docker internal hackathon project Javier designed in the first half of 2023 (referenced as completed by Aug 2023). FGPT prototyped an AI assistant inside Docker Desktop — an "Ask our assistant for help" panel that turned plain English ("Stop all the containers", "Pull latest NGINX for x86") into Docker commands to review or run, with an "✦ Assistant" entry point in the toolbar. Its sibling concepts (Docker Ask, Docker WTF) already used Gordon's core trick — sending container/image/volume context to reduce hallucinations. It's the earliest UX ancestor of Ask Gordon.

It didn't win the hackathon — but it was early and right. The overlap with today's Gordon is unmistakable: an in-Desktop assistant entry point → the Gordon sidebar; natural language → Docker commands; a "View command / Run" step → Gordon's approve/deny permission model; and environment context to reduce hallucinations. Javier prototyped the pattern in 2023; that pattern is what Gordon became — now ~119,700 MAU. Conviction ahead of the curve.

The problem

An agent that acts — safely

Docker needed an AI assistant embedded where developers already work (Desktop + CLI), without letting an agent take unsafe actions on their machine. A 0→1 bet: no established pattern, no users. The design challenge was trust — making "let the agent act" feel safe enough to ship.

My role

End-to-end design lead

Interaction model, onboarding, permission/safety UX, billing & GA flows, support integration, and the feedback research pipeline (Qualtrics → Slack). Partnered with the AI-agent engineering team, PM, and design leadership. Authored the "Ask Gordon Continuous Research Plan."

Jobs to be done

Use cases designed

  • Ask about containers/images/compose without leaving Docker (embedded in global search & tabs)
  • Let the agent act — but approve every destructive step (danger tiers + allow/deny dialog + CLI hook)
  • Understand cost, plans, and token usage (budget views, billing portal)
  • Get started without docs (onboarding, login nudge, plan mode)
  • Report failures via an in-product feedback loop I built
Process & delivery

How it shipped

Research-led and iterative: stood up a continuous feedback loop, explored many variants (free/blocked states, JIT nudges), and shipped the selected directions. Delivered the interaction model, onboarding, the safety UX (reused as the reference pattern for other agent dialogs), budget/token views, Gordon-in-Support, and the billing/GA flows — beta in Desktop 4.38, GA with 4.74 (May 2026), shipped again in 4.80.

Impact

The numbers moved

Docker's own blog describes the permission model exactly as designed: "Gordon shows you what it wants to do, you approve or reject, then it executes." — the safety UX became the product's headline trust feature.
