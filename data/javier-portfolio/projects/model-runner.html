Docker Model Runner & model cards

End-to-end UX for running LLMs locally through Docker — across Desktop, CLI, and Hub. I designed and coded the Hub model cards so developers pick the right model out of ~18,000.

The problem

Pick the right model, fast

Local inference had no first-class UX, and with ~18K models the choice was overwhelming — unclear size, quantization, task fit, and hardware needs. Picking wrong wastes a big download and erodes trust. The model card had to make the decision obvious at a glance.

My role

Full-stack design

Designed across Desktop, CLI, and Hub; designed and coded the Hub model cards and the AI Model Flow selector. Ran my own discovery — the "Docker Model Runner – Insights" report (co-authored with Francesco Corti) — which drove the card content.

Jobs to be done

Use cases designed

  • Find a model that fits my task and hardware
  • Pull & run a model from the CLI like any image
  • Decide between similar models without trial-and-error downloads
  • Manage local models inside Desktop
  • Guided onboarding for first-time AI developers
Delivery

What shipped

Desktop Model Runner UI · CLI inference UX (push/pull) · coded Hub model cards + new card layout · AI Model Flow selector · research report · handoff artifacts (Miro + a Python model-selector repo). Beta Apr 2025 → GA Sep 18, 2025 (open source, `github.com/docker/model-runner`).
